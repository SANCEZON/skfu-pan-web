# Исправление создания профиля при регистрации

## Проблема

После регистрации по коду приглашения:
- Ошибка `401 (Unauthorized)` при создании профиля
- Ошибка `406 (Not Acceptable)` при попытке получить профиль
- "Profile not found for user" - профиль не создается
- Нет заявки на одобрение

## Причина

После `signUp` сессия может быть не установлена сразу, поэтому RLS политики блокируют создание профиля через прямой INSERT.

## Решение

### Шаг 1: Применить обновленную миграцию

1. Откройте **Supabase Dashboard → SQL Editor**
2. Скопируйте содержимое файла `supabase/migrations/008_fix_auth_users_access.sql` (обновленный)
3. Вставьте в SQL Editor и выполните

Эта миграция:
- Создает функцию `create_user_profile()` для безопасного создания профиля
- Функция использует `SECURITY DEFINER` и работает даже если сессия не полностью установлена
- Пересоздает политику INSERT для `user_profiles`

### Шаг 2: Проверить регистрацию

После применения миграции:

1. Обновите страницу приложения (F5)
2. Перейдите на страницу входа
3. Нажмите "Нет аккаунта? Зарегистрироваться"
4. Введите:
   - Email (должен совпадать с email в приглашении)
   - Пароль
   - Код приглашения
5. Нажмите "Зарегистрироваться"

### Шаг 3: Проверить результат

После регистрации:
- Должен появиться экран "Заявка на одобрение"
- В консоли не должно быть ошибок 401 или 406
- Профиль должен быть создан со статусом `pending`

### Шаг 4: Проверить в базе

Выполните в SQL Editor:

```sql
-- Проверьте, что профиль создан
SELECT * FROM user_profiles 
WHERE user_id = 'USER_ID_HERE';

-- Проверьте статус приглашения
SELECT * FROM user_invitations 
WHERE id = 'INVITATION_ID_HERE';
```

## Что было исправлено

1. **Создана функция `create_user_profile()`:**
   - Использует `SECURITY DEFINER` для безопасного создания профиля
   - Работает даже если сессия не полностью установлена
   - Проверяет, что пользователь создает только свой профиль

2. **Обновлена логика регистрации:**
   - Использует RPC функцию вместо прямого INSERT
   - Добавлен fallback на прямой INSERT, если функция не работает
   - Добавлена задержка перед получением профиля
   - Улучшена обработка ошибок

3. **Пересоздана политика INSERT:**
   - Убеждается, что политика работает правильно
   - Разрешает пользователям создавать свой профиль

## После исправления

- ✅ Профиль создается автоматически при регистрации
- ✅ Профиль имеет статус `pending`
- ✅ Пользователь видит экран "Заявка на одобрение"
- ✅ Приглашение обновляется на статус `accepted`

## Если проблема сохраняется

1. Убедитесь, что миграция `008_fix_auth_users_access.sql` применена полностью
2. Проверьте логи в консоли браузера:
   - `User created, creating profile...` - должно появиться
   - `Profile created, updating invitation...` - должно появиться
   - Не должно быть ошибок 401 или 406
3. Проверьте, что функция существует:
   ```sql
   SELECT proname FROM pg_proc WHERE proname = 'create_user_profile';
   ```
4. Проверьте, что политика существует:
   ```sql
   SELECT * FROM pg_policies WHERE tablename = 'user_profiles' AND policyname = 'Users can insert own profile';
   ```

## Важно

- После регистрации пользователь должен увидеть экран "Заявка на одобрение"
- Администратор должен одобрить пользователя в разделе "Приглашения"
- Только после одобрения пользователь получит доступ к панели
