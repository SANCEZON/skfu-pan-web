# Исправление ошибок 403 для приглашений

## Проблема

В консоли браузера видны ошибки:
- `403 (Forbidden)` на запросы к `user_invitations`
- `permission denied for table users` (код ошибки 42501)

## Причина

RLS политики пытались обращаться напрямую к таблице `auth.users`, что запрещено в Supabase. Политики не могут напрямую читать из `auth.users`.

## Решение

### Шаг 1: Применить миграцию исправления

1. Откройте **Supabase Dashboard → SQL Editor**
2. Скопируйте содержимое файла `supabase/migrations/008_fix_auth_users_access.sql`
3. Вставьте в SQL Editor и выполните

Эта миграция:
- Создает функцию `get_user_email()` для безопасного получения email пользователя
- Исправляет политики RLS для `user_invitations`, чтобы они использовали функцию вместо прямого доступа к `auth.users`
- Добавляет отдельную политику для INSERT, чтобы approved пользователи могли создавать приглашения

### Шаг 2: Проверить работу

После применения миграции:

1. Обновите страницу приложения (F5)
2. Откройте консоль браузера (F12)
3. Проверьте, что ошибки 403 исчезли
4. Попробуйте:
   - Открыть страницу "Приглашения"
   - Создать новое приглашение
   - Просмотреть список приглашений

### Шаг 3: Проверить функцию

Выполните в SQL Editor:

```sql
-- Проверьте, что функция работает
SELECT public.get_user_email();

-- Проверьте, что функция доступна
SELECT public.is_user_approved();
```

## Что было исправлено

1. **Создана функция `get_user_email()`:**
   - Использует `SECURITY DEFINER` для безопасного доступа к `auth.users`
   - Возвращает email текущего пользователя
   - Доступна для всех authenticated и anon пользователей

2. **Исправлены политики RLS:**
   - Политики теперь используют `get_user_email()` вместо прямого доступа к `auth.users`
   - Добавлена отдельная политика для INSERT приглашений

3. **Обновлена миграция 007:**
   - Временно упрощены политики, чтобы избежать ошибок
   - Миграция 008 полностью исправляет проблему

## После исправления

- ✅ Approved пользователи могут создавать приглашения
- ✅ Approved пользователи могут просматривать все приглашения
- ✅ Пользователи могут видеть приглашения со своим email
- ✅ Пользователи могут обновлять свои приглашения (при принятии)

## Если проблема сохраняется

1. Убедитесь, что миграция `008_fix_auth_users_access.sql` применена
2. Проверьте, что пользователь имеет статус `approved`:
   ```sql
   SELECT status FROM user_profiles WHERE user_id = auth.uid();
   ```
3. Проверьте логи в Supabase Dashboard → Logs
4. Проверьте, что функция `get_user_email()` возвращает email
