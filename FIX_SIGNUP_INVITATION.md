# Исправление регистрации по коду приглашения

## Проблема

При попытке зарегистрироваться по коду приглашения возникает ошибка `406 (Not Acceptable)` или `403 (Forbidden)`. Это происходит потому, что анонимные пользователи (не авторизованные) не могут читать приглашения из-за RLS политик.

## Решение

### Шаг 1: Применить обновленную миграцию

1. Откройте **Supabase Dashboard → SQL Editor**
2. Скопируйте содержимое файла `supabase/migrations/008_fix_auth_users_access.sql` (обновленный)
3. Вставьте в SQL Editor и выполните

Эта миграция:
- Создает функцию `get_invitation_by_token()` для безопасной проверки токена приглашения
- Функция работает для анонимных пользователей (использует `SECURITY DEFINER`)
- Проверяет, что приглашение имеет статус `pending` и не истекло

### Шаг 2: Проверить работу

После применения миграции:

1. Обновите страницу приложения (F5)
2. Перейдите на страницу входа
3. Нажмите "Нет аккаунта? Зарегистрироваться"
4. Введите:
   - Email (должен совпадать с email в приглашении)
   - Пароль
   - Код приглашения
5. Нажмите "Зарегистрироваться"

### Шаг 3: Проверить логи

Откройте консоль браузера (F12) и проверьте логи:
- `Checking invitation with token:` - показывает проверку токена
- `Invitation data:` - показывает данные приглашения
- `Invitation validated, creating user account...` - показывает успешную валидацию

## Что было исправлено

1. **Создана функция `get_invitation_by_token()`:**
   - Использует `SECURITY DEFINER` для доступа к приглашениям
   - Работает для анонимных пользователей
   - Проверяет статус `pending` и срок действия

2. **Обновлена логика регистрации:**
   - Использует RPC функцию вместо прямого запроса к таблице
   - Улучшена обработка ошибок
   - Добавлено логирование для диагностики

3. **Обновлена политика RLS:**
   - Добавлена возможность для анонимных пользователей читать pending приглашения
   - Это работает через функцию, а не напрямую

## Проверка функции

Выполните в SQL Editor:

```sql
-- Проверьте, что функция существует
SELECT proname FROM pg_proc WHERE proname = 'get_invitation_by_token';

-- Проверьте, что функция доступна
GRANT EXECUTE ON FUNCTION public.get_invitation_by_token(TEXT) TO anon;
GRANT EXECUTE ON FUNCTION public.get_invitation_by_token(TEXT) TO authenticated;

-- Протестируйте функцию (замените TOKEN на реальный токен)
SELECT * FROM public.get_invitation_by_token('TOKEN_HERE');
```

## Если проблема сохраняется

1. Убедитесь, что миграция `008_fix_auth_users_access.sql` применена полностью
2. Проверьте, что приглашение существует и имеет статус `pending`:
   ```sql
   SELECT * FROM user_invitations WHERE token = 'TOKEN_HERE';
   ```
3. Проверьте, что приглашение не истекло:
   ```sql
   SELECT * FROM user_invitations 
   WHERE token = 'TOKEN_HERE' 
   AND (expires_at IS NULL OR expires_at > NOW());
   ```
4. Проверьте логи в консоли браузера для детальной информации об ошибках

## Важно

- Email при регистрации должен точно совпадать с email в приглашении
- Приглашение должно иметь статус `pending`
- Приглашение не должно быть истекшим (если указан `expires_at`)
- Код приглашения должен быть введен точно (чувствителен к регистру, если используется)
